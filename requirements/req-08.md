# 8. 블라인드 프로필 공개

> 출처: PPT 13쪽. 원문을 템플릿에 옮기고 표기(공백 제거, enum 값, 대표 용어)만 맞췄다. CONVENTIONS 4장 규칙에 맞게 다듬는 것은 담당자가 한다.

## 명세

**Function:** 블라인드 프로필 공개

**Description:** 처음에는 프로필 사진만 보여주고, 같은 테이블 출석 학생 모두가 동의할 때마다 MBTI → 학과 → 학번 순으로 한 단계씩 공개한다.

**Input:** 모임 ID, 최종배치의 테이블 번호, 학생별 공개 동의

**Source:** 학생UI, 프로필DB, 배치DB, 출석DB

**Output:** 단계별 공개 정보, 동의 인원수

**Destination:** 학생UI

**Action:**

1. 같은 테이블 출석 학생이 '정보 공개'를 누르면 시스템은 배치DB에서 해당 테이블의 최종배치를 확인하고 출석DB에서 같은 테이블 출석 인원을 조회한다. 현재 단계의 동의를 기록하고 '○명 중 ○명 동의'를 표시한다.
2. 해당 테이블의 같은 테이블 출석 학생 전원이 현재 단계에 동의하면 프로필DB에서 해당 항목을 조회하여 1단계 MBTI, 2단계 학과, 3단계 학번 중 해당 항목을 공개한다. 전원이 동의하지 않으면 현재 단계에서 동의를 기다린다.
3. 현재 단계의 동의 상태를 초기화하고 다음 단계로 올려 Action 1을 반복한다. 3단계가 완료되면 처리를 종료한다.

**Requirements:** 모든 동의 인원은 배치DB에 저장된 최종배치 기준 같은 테이블 출석 학생으로 고정한다. 모임 종료 후에는 공개 정보를 다시 조회할 수 없도록 학생UI 접근을 차단한다.

**Pre-condition:** 배치DB에 해당 모임의 최종배치가 저장되어 있고 같은 테이블 출석 학생이 2명 이상이다. 해당 학생들이 필요한 프로필 항목을 등록했다.

**Post-condition:** 전원 동의한 단계만 학생UI에 표시된다.

**Side effects:** 단계별 공개 동의 상태가 기록되고 갱신된다.
