# 6. 1인 잔류 테이블 합석

> 출처: PPT 11쪽 6. 1인 잔류 테이블 합석(수정). 원문을 템플릿에 옮기고 표기(공백 제거, enum 값, 대표 용어)만 맞췄다.

## 명세

**Function:** 1인 잔류 테이블 합석

**Description:** 출석 가능 시간이 끝나면 혼자 출석한 학생을 다른 출석 학생이 있는 테이블로 합석시킨다.

**Input:** 모임 ID, 출석 기록, 출석 학생의 학과, 테이블 배치

**Source:** 모임DB, 출석DB, 배치DB, 프로필DB

**Output:** 변경된 테이블 번호, 추가 의자, 합석 알림, 최종배치

**Destination:** 배치DB, 학생UI, 사장님UI

**Action:**

1. 출석 가능 시간(모임 시작 10분 후)이 끝나면 시스템은 모임DB에서 모임 상태를 조회한다. 모임 상태가 '취소'이면 사장님UI에 알리고 처리를 종료한다.
2. 배치DB에서 테이블별 배정 학생, 테이블 정원, 추가 의자를, 출석DB에서 출석 기록을 조회해 테이블별 출석 인원을 센다. 출석 학생이 1명뿐인 테이블이 1인 잔류 테이블이다.
3. 1인 잔류 테이블을 번호가 작은 순서로 하나 고른다. 모임 전체 출석 학생이 1명이거나 1인 잔류 테이블이 없으면 6단계로 간다.
4. 프로필DB에서 혼자 출석한 학생과 다른 출석 학생들의 학과를 조회해 옮겨 갈 테이블을 고른다. 후보는 다른 출석 학생이 있고 빈 좌석이 1개 이상인 테이블이다. 빈 좌석은 테이블 정원과 추가 의자를 더한 수에서 출석 인원을 뺀 값이다. 후보 중 같은 학과 학생이 없는 테이블을 우선하고, 그다음은 출석 인원이 가장 적은 테이블, 그다음은 번호가 작은 테이블 순이다.
    1. 후보가 없으면 번호가 가장 작은 출석 테이블에 의자 1개를 추가하고 사장님UI에 알린다.
5. 배치DB에서 학생의 테이블 번호와 추가 의자를 갱신하고, 학생UI로 합석한 학생들에게 바뀐 테이블 번호를 알린 뒤 3단계로 돌아간다.
6. 합석이 끝난 배치를 배치DB에 최종배치로 저장하고 처리를 종료한다.

**Requirements:** 합석하는 학생은 기존 테이블에서 빠지고 대상 테이블에 한 번만 포함된다. 한 번 옮긴 학생은 다시 옮기지 않는다.

**Pre-condition:** 배치DB에 해당 모임의 배치가 저장되어 있고, 출석DB에 출석 가능 시간 동안 QR 출석 또는 사장님확인으로 출석한 학생의 출석 기록이 저장되어 있다. 출석 가능 시간(모임 시작 10분 후)이 종료되었다.

**Post-condition:** 합석한 학생의 테이블 번호가 배치DB에 갱신되었고, 합석 가능한 1인 잔류 테이블이 없어졌다. 배치DB에 최종배치가 저장되었다.

**Side effects:** 배치DB에 합석 이력(바뀐 테이블 번호, 추가 의자)이 기록된다. 합석 알림과 의자 추가 알림 푸시가 발송된다. 출석 가능 시간이 끝나는 시각이 같은 모임이 많으면 처리가 한꺼번에 몰린다.
