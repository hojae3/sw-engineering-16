# 13. 비매너 학생 이용 정지

> 출처: PPT 18쪽. 원문을 템플릿에 옮기고 표기(공백 제거, enum 값, 대표 용어)만 맞췄다. CONVENTIONS 4장 규칙에 맞게 다듬는 것은 담당자가 한다.

## 명세

**Function:** 비매너 학생 이용 정지

**Description:** 접수된 비매너 신고에 대해 앱운영자가 심사를 진행하여 '유효'로 판정한 누적 건수가 3건에 도달하거나, 앱운영자가 1건이라도 '중대위반'으로 승인하면 학생 계정을 정지해 모임 신청을 차단한다.

**Input:** 신고 대상 학생 ID, 신고 내역, 앱운영자 심사 결과(유효/중대위반/반려), 정지 사유

**Source:** 신고DB, 프로필DB, 신청DB, 결제DB, 앱운영자

**Output:** 계정 정지 결과, 이용 정지 안내, 신청 자동 취소·환급 결과

**Destination:** 프로필DB, 정지DB, 신청DB, 결제DB, 학생UI

**Action:**

1. 신고DB에 새로운 신고가 접수되면, 앱운영자는 신고DB의 신고 사유와 상세 내용을 심사하여 해당 신고를 '유효', '중대위반', '반려' 중 하나로 신고DB에 저장한다.
2. '반려'인 경우 신고DB에 심사 결과를 저장하고 처리를 종료한다.
3. 시스템은 신고DB를 조회하여 해당 학생에게 누적된 신고 중 앱운영자가 '유효' 승인한 신고 건수만을 합산하여 '누적 유효 신고 건수'를 계산한다.
4. 누적 유효 신고 건수가 3건 이상이거나 앱운영자가 '중대위반'으로 신고를 승인하면,
    - 프로필DB 계정 상태를 '정지'로 변경한다.
    - 정지DB에 학생 ID와 정지 사유를 저장하고 학생UI에 이용 정지 안내를 보낸다.
    - 신청DB를 조회하여 아직 시작되지 않은 해당 학생의 '결제완료' 모임 신청 건이 있는지 확인한다.
        - 신청 건이 존재한다면, 신청DB 상태를 '신청취소'로 변경하고 결제DB를 통해 결제한 참가비 전액을 환급한다.
        - 신청 건이 없다면 처리를 종료한다.
5. 누적 유효 신고 건수가 3건 미만이고 중대위반 승인이 아닌 경우, 계정 상태를 변경하지 않고 심사 결과만 신고DB에 저장한 뒤 처리를 종료한다.

**Requirements:** 계정 정지 후에는 모임 신청을 할 수 없다. 정지는 영구적이며 자동 해제는 적용하지 않는다. '반려' 처리된 신고는 누적 유효 신고 건수에서 제외한다.

**Pre-condition:** 신고DB에 심사되지 않은 접수 상태의 신고 내역이 저장되어 있다.

**Post-condition:** 정지 대상 학생은 프로필DB 계정 상태가 정지로 바뀌고 정지DB에 기록된다.

**Side effects:** 정지DB에 정지 내역이 추가되고 프로필DB의 계정 상태가 '정지'로 갱신된다. 정지된 학생에게 이용 정지 푸시 알림이 발송되며, 해당 학생이 기존에 신청했던 '모집중' 모임 참가비 환급 처리가 발생한다.
