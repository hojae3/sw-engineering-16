# 3. 친해지고 싶은 학생 알림

> 출처: PPT 6쪽. 원문을 템플릿에 옮기고 표기(공백 제거, enum 값, 대표 용어)만 맞췄다. CONVENTIONS 4장 규칙에 맞게 다듬는 것은 담당자가 한다.

## 명세

**Function:** 친해지고 싶은 학생 알림

**Description:** 관심 대상으로 등록된 학생의 모임 신청 결제가 완료되면, 그 학생을 등록한 다른 학생들에게 확률적으로 신청 공지 알림을 보낸다. 등록 인원이 많을수록 확률을 줄인다.

**Input:** 신청한 학생 ID, 모임 ID, 관심 대상으로 등록한 학생 목록 및 인원수

**Source:** 신청DB, 관심등록DB, 모임DB

**Output:** 푸시 알림, 해당 모임 공지 연결 정보

**Destination:** 학생UI

**Action:**

1. 신청DB에 신청 상태 '결제완료'가 저장되면 시스템은 관심등록DB를 조회하여, 해당 학생을 관심 대상으로 등록한 학생 ID 목록을 추출한다.
2. 목록이 비어 있는 경우, 시스템은 학생UI에 알림 대상이 없음을 알리고 처리를 종료한다.
3. 조회된 목록이 비어있지 않다면, 목록의 인원수를 n으로 두고 각 학생에 대한 알림 확률 p = 1/n을 계산한다.
4. 각 학생별 독립적인 확률 판정으로 알림 발송 대상을 정하고 알림 권한이 허용된 대상에게 푸시 알림을 보낸다.
5. 확률 판정에서 탈락하거나 알림 권한이 허용되지 않은 학생은 알림 발송 대상에서 제외한다.
6. 알림을 받은 학생이 알림을 누르면 해당 모임 공지 화면으로 이동한다.

**Requirements:** 같은 신청 건으로 여러 번 알림을 보내지 않는다. 알림을 받지 않은 학생에게 신청한 학생의 정보를 추가로 노출하지 않는다. 발송 대상은 모임 모집 마감 전에 신청 가능한 학생으로 제한한다. (확률 p = 1/n 설계는 특정 인기 학생에 대한 모임 독점 및 쏠림을 방지하기 위한 제약 조건으로 적용한다.)

**Pre-condition:** 신청DB에 신청 상태가 '결제완료'인 신청 건이 존재하고 모임DB의 모임 상태가 '모집중'이다. 관심등록DB에 관심 등록 관계가 저장되어 있을 수 있다.

**Post-condition:** 확률에 선정되고 알림 권한을 허용한 학생에게 해당 모임 알림이 표시된다.

**Side effects:** 친해지고 싶은 학생으로 등록한 학생 중 확률 판정에 선정된 학생들에게 푸시 알림이 발송된다.
