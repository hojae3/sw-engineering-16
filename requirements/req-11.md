# 11. 친해지고 싶은 학생 등록

> 출처: PPT 16쪽. 원문을 템플릿에 옮기고 표기(공백 제거, enum 값, 대표 용어)만 맞췄다. CONVENTIONS 4장 규칙에 맞게 다듬는 것은 담당자가 한다.

## 명세

**Function:** 친해지고 싶은 학생 등록

**Description:** 평가 완료 후 '친해지고 싶은 학생 등록' 화면을 학생UI에 표시해 같은 테이블 출석 학생 중 친해지고 싶은 학생을 등록한다. 향후 해당 학생이 새 모임에 신청했을 때 알림을 받기 위한 데이터로 저장된다.

**Input:** 등록하는 학생 ID, 관심 대상으로 등록될 학생 ID, '건너뛰기' 선택 여부

**Source:** 학생UI, 관심등록DB, 배치DB, 출석DB, 프로필DB

**Output:** 관심 등록 관계, 등록 완료·중복 등록 안내

**Destination:** 관심등록DB, 학생UI

**Action:**

1. 평가DB에 학생의 평가가 저장되면 시스템은 배치DB와 출석DB에서 본인을 제외한 같은 테이블 출석 학생 목록을 조회하고, 프로필DB에서 해당 학생들의 프로필 사진을 가져와 '친해지고 싶은 학생 등록' 화면을 학생UI에 표시한다.
2. 친해지고 싶은 학생이 없어 '건너뛰기'를 누르면, 관심등록DB에 기록하지 않고 학생UI에 등록 생략을 알린 뒤 처리를 종료한다.
3. 학생이 대상 학생의 프로필 사진에서 '친해지기'를 누른다.
4. 시스템은 관심등록DB에서 '등록하는 학생 ID'와 '관심 대상으로 등록될 학생 ID'가 일치하는 데이터가 이미 존재하는지 확인한다.
    - 이미 존재한다면, 학생UI에 '이미 등록된 학생입니다'를 표시하고 처리를 종료한다.
    - 존재하지 않는다면, 관심등록DB에 등록하는 학생 ID, 관심 대상으로 등록될 학생 ID를 저장하고 학생UI에 '친해지고 싶은 학생으로 등록되었습니다'를 표시한 뒤 처리를 종료한다.

**Requirements:** 관심 대상으로 등록되었다는 사실이나 등록한 학생의 신원은 상대 학생에게 공개하지 않는다. 같은 테이블 출석 학생 목록은 출석DB에 출석 기록이 있는 동일 테이블 출석 학생으로 한정한다.

**Pre-condition:** 평가DB에 해당 모임에서 본인의 평가 내역이 저장되어 있고, 출석DB에 출석 기록이 있다.

**Post-condition:** 신규 등록 시 관심등록DB에 관계가 저장된다.

**Side effects:** 관심등록DB에 학생 선택 기록이 추가되어 저장 데이터가 증가하며, 이후 모임의 상호 관심 알림 매칭에 활용되므로 삭제하지 않고 보존한다.
