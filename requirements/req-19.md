# 19. 모임 다음 날 숙취 예보

> 출처: PPT 27쪽. 원문을 템플릿에 옮기고 표기(공백 제거, enum 값, 대표 용어)만 맞췄다. 계산식의 floor 기호는 한글로 풀어 썼다. CONVENTIONS 4장 규칙에 맞게 다듬는 것은 담당자가 한다.

## 명세

**Function:** 모임 다음 날 숙취 예보

**Description:** 모임 종료 후 테이블 술 주문량과 모임 종료 시각으로 참고용 숙취 지수를 계산하여 다음 날 아침 같은 테이블 출석 학생에게 알린다.

**Input:** 모임 ID, 최종배치의 테이블별 술 주문 병 수, 출석 인원, 모임 종료 시각, 제휴 쿠폰

**Source:** 주문DB, 출석DB, 배치DB, 모임DB, 가게DB

**Output:** 숙취 예보 알림, 해당 시 제휴 쿠폰

**Destination:** 학생UI

**Action:**

1. 다음 날 08:00에 시스템은 모임DB에서 전날 종료된 모임과 모임 종료 시각을 조회한다.
2. 모임의 테이블마다 배치DB에서 같은 테이블 학생을 조회하고, 출석DB에서 출석 학생만 거른다. 출석 인원이 0인 테이블은 제외한다.
3. 주문DB에서 테이블별 술 주문 병 수를 조회해 숙취 지수를 계산한다. 술 주문 병 수를 해당 테이블 출석 인원으로 나누고 다시 2로 나눈 값의 소수점 아래를 버린 뒤, 모임 종료 시각이 23시 이후이면 1을 더한다. 3보다 크면 3으로 한다.
4. 지수가 2단계 이상이면 가게DB에서 제휴 쿠폰을 조회한다. 쿠폰이 있으면 '오늘의 숙취 예보: ○단계'와 쿠폰을, 없으면 예보만 같은 테이블 출석 학생에게 보낸다.
5. 지수가 2단계 미만이면 예보만 보낸다. (0 맑음, 1 구름 조금, 2 흐림, 3 비)

**Requirements:** 같은 테이블 출석 학생은 같은 지수를 받는다. 지수는 실제 개인 음주량이나 건강 상태를 진단하는 수치가 아니라고 알린다. 쿠폰이 등록되지 않았다면 예보만 발송한다.

**Pre-condition:** '9. 자동 정산'에서 주문DB가 마감되었고, '6. 1인 잔류 테이블 합석'으로 최종배치가 정해졌다. 모임 종료 시각은 '1. 모임공지등록'에서 입력되었다. 앱운영자가 해장 가게의 제휴 쿠폰을 가게DB에 등록해 두었다. 매일 08:00에 숙취 예보 작업이 자동 실행된다.

**Post-condition:** 다음 날 08:00에 같은 테이블 출석 학생에게 예보가 발송되며 조건에 해당하면 쿠폰도 함께 전송된다.

**Side effects:** 매일 08:00에 전날 모임 출석 학생들을 대상으로 숙취 예보 푸시 알림 발송이 한꺼번에 집중된다.

## 정리할 것

- PPT의 "바꾸는 이유" 상자 내용(다음 날 08:00에 계산과 발송을 한 번에)은 반영된 상태다.
- Action 1: 전날 종료된 모임이 없을 때의 else 동작을 쓴다. 시퀀스는 `시간` 액터로 시작한다.
- Action 2: 같은 테이블 출석 학생·출석 인원 조회는 공통 객체 테이블출석현황을, 술 주문 병 수는 공통 객체 술주문집계 후보를 쓴다 (GLOSSARY 5장).
- Pre-condition에서 다른 기능 이름을 빼고 DB 상태로 쓴다 (예: 주문DB가 마감되었고 배치DB에 최종배치가 저장되어 있다). "매일 08:00에 숙취 예보 작업이 자동 실행된다"는 시작 조건이므로 Action 1에 이미 있다.
