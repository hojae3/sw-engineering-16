기존 [usecase.md](usecase.md)는 그대로 두고, 11/10 교수님 미팅([meeting/1110.md](../meeting/1110.md), FEEDBACK #21·#22) 기준으로 새로 만든 비교용 초안이다.

**미리보기 그림 (v2):** https://claude.ai/artifact/USiRDKMmv1kGZ58v518VUe — 모임 전·중·후는 주소 끝에 `#stage-pre`, `#stage-mid`, `#stage-post`, 요구사항별은 `#req-번호` (예: `#req-17`)

| | 기존 usecase.md | 이 초안 (v2) |
|---|---|---|
| 유스케이스 단위 | 요구사항 하나 = 타원 하나 (20개) | 요구사항 Action에서 **액터가 직접 하는 행동** 하나 = 타원 하나 (30개) |
| 이름 | 기능명 그대로 (명사형) | 액터 목적 + **동사** (예: 대화카드시작하기) |
| '시간' 액터 | 있음 (6, 9, 19) | **없음**. 시각으로 시작하는 기능은 시스템 내부 타이머로 시작하고, 결과를 받는 액터만 잇는다 |
| 그리는 장수 | 전체 한 장 | **요구사항마다 한 장 (20장)** + **모임 전 / 모임 중 / 모임 후 3장** |
| 다른 다이어그램과의 연결 | 기능명 | 유스케이스마다 **요구사항 번호와 시퀀스 메시지 번호**를 적는다 |

> **이 초안대로 그리려면 규칙을 바꿔야 한다.** 아직 규칙은 바꾸지 않았다. 바꿔야 할 곳은 맨 아래 "이 초안을 쓰려면 바꿔야 할 규칙"에 정리했다.

## include / extend

| 화살표 시작 | 관계 | 화살표 끝 | 요구사항 | 근거 |
|---|---|---|---|---|
| 참가비결제하기 | «include» | 학년별참가비확인하기 | 2-2 → 2-1 | 결제하려면 학년별 참가비 확인이 항상 먼저 필요하다 (기존 2-2 «include» 2-1과 같음) |
| 사장님확인으로출석처리하기 | «extend» | QR로상호출석하기 | 5 | 상호 스캔할 상대가 없을 때만 사장님이 확인한다 |
| 대화카드시작하기 | «include» | 카드정답맞히기 | 7 | 카드를 시작하면 정답 고르기가 항상 따라온다 |
| 다음카드받기 | «extend» | 대화카드시작하기 | 7 | 학생이 '다음 카드'를 누를 때만 일어난다 |
| 안전응답하기 | «extend» | 안심귀가확인받기 | 15 | 귀가 마감 시각까지 도착하지 못했을 때만 안전 응답을 요청한다 |
| 친해지고싶은학생등록하기 | «extend» | 같은테이블학생매너평가하기 | 11 → 10 | 평가가 끝난 뒤 하며 '건너뛰기'가 있어 선택 사항이다 (기존과 같음) |

- 16의 기부참여하기, 17의 교환요청에응답하기는 **다른 학생**이 하는 행동이라 extend로 잇지 않는다 (11/08 3 «extend» 2-2 삭제와 같은 이유).
- 18-1의 대기 취소는 2026-11-10에 요구사항에서 뺐다 (등록한 대기는 취소할 수 없음). 유스케이스로 그리지 않는다.

## 그리는 장수

### 요구사항마다 한 장 (20장)

각 장에는 그 요구사항의 유스케이스(1~3개), 연결 액터, 그 요구사항 안의 include/extend를 그린다. 요구사항을 넘는 관계(2-2 → 2-1, 11 → 10)는 양쪽 장에 상대 유스케이스도 같이 그린다.

| 타원 1개 | 타원 2개 | 타원 3개 |
|---|---|---|
| 1, 2-1, 3, 4-2, 6, 8, 9, 12, 13, 18-1, 19 | 2-2(+2-1), 5, 10(+11), 11(+10), 15, 16, 18-2, 20 | 7, 17 |

| 장 | 유스케이스 수 | 액터 |
|---|---|---|
| 모임 전 | 5 | 학생, 사장님, 결제서비스 |
| 모임 중 | 17 | 학생, 사장님, 앱운영자, 단말기위치정보 |

## 이 초안을 쓰려면 바꿔야 할 규칙

아직 바꾸지 않았다. 팀에서 이 초안으로 가기로 하면 아래를 같이 고친다.

| 규칙 | 지금 | 바꿀 내용 | 근거 |
|---|---|---|---|
| CONVENTIONS 7장 | 유스케이스 이름 = 요구사항 기능명 (공백 제거) | 유스케이스 = 요구사항 Action에서 액터가 직접 하는 행동. 이름은 목적 + 동사. 요구사항 번호와 시퀀스 메시지 번호를 같이 적는다 | FEEDBACK #22 |
| CONVENTIONS 7장, usecase.md 제목 | 전체 시스템 한 장 | 요구사항마다 한 장 + 모임 전/중/후 3장. 전체 한 장은 그리지 않는다 | 팀 결정 (11/10) |
| CONVENTIONS 7장 연결 규칙 | 시각으로 시작 → `시간`과 연결 | 시각으로 시작 → 시스템 내부 타이머로 시작하고, 결과를 받는 액터와 연결 | FEEDBACK #21 |
| GLOSSARY 1장 | `시간` 액터 | 액터에서 삭제 (시퀀스 쪽 처리는 #21·#29와 같이 정한다) | FEEDBACK #21 |
| GLOSSARY 9장 | 스케줄러 → 시간 (액터) | 시퀀스에서 스케줄러를 쓸지 정하고 고친다 | FEEDBACK #21·#29 |
| CONVENTIONS 8.3 | usecase.md의 표를 그대로 옮긴다 | 이 파일의 표를 옮긴다 | |
| usecase.md | 기존 표 | 이 파일 내용으로 바꾸고 이 파일은 지운다 | |

- 시퀀스·클래스는 이 초안 때문에 고칠 것이 없다. 시퀀스 메시지 칸이 이미 있는 메시지를 가리킨다.
