# 18번 화장실 기능 최종 발표안 (2장)

최종 발표에서는 20개 기능 중 8개 안팎만 보여 준다 (교수님). 화장실 기능은 1~2장으로 "한 칸 화장실에 방광 게이지 우선으로 조를 짜서 안전하게 들여보낸다"는 의미가 보이게 정리했다.

| 장 | 기능 | 시작 | 보여 주는 것 | 메시지 |
|---|---|---|---|---|
| ① [req](req-18-1.md) · [seq](seq-18-1.md) | 화장실 대기 등록 | 학생이 '소변 입장'을 누름 | 방광 게이지 계산, 공통 객체(테이블) 재사용, 우선순위 조 편성, 동기 응답 뒤 처리 | 14 |
| ② [req](req-18-2.md) · [seq](seq-18-2.md) | 화장실 입장 및 퇴실 | 화장실이 빔 (Found) | 첫 조 입장, 스케줄러 등록 → 콜백, 학생·사장님 두 액터, 실패(3분 미확인) 흐름 | 19 |

**1장만 보여 줄 때는 ①**을 쓰고, "화장실이 비면 ②가 대기 조를 들여보내고, 퇴실하면 다시 ②가 시작된다"를 한 줄로 말한다 (#41 연결은 끊어져도 정합성은 있게).

## 두 장이 이어지는 모습

```
① 대기 등록 ──(대기 저장, 화장실이 비어 있을 때)──▶ ② 입장 및 퇴실
① 대기 등록 ──(조 저장, 화장실이 사용 중일 때)──▶ (기다림) ──(퇴실로 비어있음 저장)──▶ ②
② 퇴실 저장 ──▶ ② (다음 조)
```

- 화장실이 비어 있으면 ①은 조를 만들지 않는다. 대기 저장으로 ②가 바로 시작되어 그 학생을 들여보낸다. 두 기능이 같은 학생을 동시에 바꾸지 않게 하려는 것이다.
- ②에서 대기 조가 없으면 ①과 같은 조편성 함수로 '대기' 학생 중 최대 K명을 골라 들여보낸다.

## 기존 초안에서 정리한 것

| 바탕 | 정리 |
|---|---|
| [../18-1/](../18-1/), [../18-2/](../18-2/) (6cf006a) | 가게조회 삭제 (설비조회가 모임ID로 바로 돌려줌), 화장실 «module»의 입장목록 속성 삭제 (DB의 '이용' 상태로 앎), 메시지 이름·메모 정리 |
| 5개 분리안 (삭제) | 시작 조건마다 18-1~18-5로 나누면 장마다 5~9개로 너무 작아서, 발표용으로는 ①·② 두 장으로 다시 묶었다 |

- ②는 시작 사건이 셋(화장실이 빔, 학생의 해결 완료, 확인 시각)이다. 해결 완료는 loop, 확인 시각은 opt로 넣어 입장부터 퇴실까지 한 장에서 읽히게 했다. "시작 조건으로 나눈다"(4.5)와 어긋난다는 질문이 나오면, 시작 조건마다 나누면(대기 등록, 조 편성, 입장, 해결 완료, 미확인 처리) 장마다 5~9개로 너무 작아 발표용으로 묶었다고 답한다.
